Entwickler-Tools
Die GitHub-Version von thomas-bade.de

Kurz zusammengefasst
  • Alle Fachseiten von thomas-bade.de liegen als offener Quellcode im GitHub-Repository ThomasBade/website.
  • Zusätzlich enthält das Repository einen Knowledge Graph mit maschinenlesbaren Daten (JSON, JSON-LD, Markdown) unter knowledge-graph/data/.
  • Eine automatisch aktualisierte Spiegelversion läuft über GitHub Pages unter thomasbade.github.io/website; inhaltlich maßgeblich bleibt www.thomas-bade.de.

Der Inhalt dieser Website – EU AI Act, ISO/IEC 42001, KI-Governance im Gesundheits- und Sozialwesen – wird nicht nur als Webseite veröffentlicht, sondern auch als offener Quellcode bereitgestellt. Diese Seite erklärt, was in diesem Repository steckt und was Entwickler, Datenjournalisten, Forschende oder KI-Agenten damit tun können.

Was ist im Repository enthalten?

Das GitHub-Repository github.com/ThomasBade/website enthält den vollständigen statischen Quellcode der Website:

*.htmlRund 50 Fachseiten zu EU AI Act, ISO/IEC 42001, MDR/IVDR, Pflegekompetenz, internationalen Berichten und mehr – derselbe Inhalt wie auf www.thomas-bade.de.
knowledge-graph/Das GEO-Dashboard sowie der maschinenlesbare Knowledge Graph unter knowledge-graph/data/, u. a. pages.json (Seitendaten) und graph.json (semantische Verknüpfungen zwischen den Seiten).
README.mdEinstiegspunkt mit allen relevanten Links und einer Kurzbeschreibung des Projekts.
CITATION.cffMaschinenlesbare Zitierangaben (GitHub-Zitierfunktion) für Autor, Titel und kanonische URL.
METHODOLOGY.mdDokumentiert, wie die Seiteninhalte erfasst, verknüpft und bewertet werden (SEO-/GEO-Score, Datenpipeline, Grenzen der Bewertung).
llms.txtStrukturierter Einstiegspunkt für LLMs und KI-Agenten nach der llms.txt-Konvention.
.github/GitHub-Actions-Workflow, der das Repository automatisiert über GitHub Pages veröffentlicht.
LICENSE.mdNutzungsbedingungen für Quellcode und Knowledge-Graph-Daten: CC BY-NC-SA 4.0.

Was können Entwickler damit machen?

1. Repository klonen oder forken

Der Quellcode lässt sich lokal auslesen, durchsuchen oder als Fork weiterverwenden:

git clone https://github.com/ThomasBade/website.git

2. Maschinenlesbare Daten auswerten

Statt HTML zu parsen, können die strukturierten Exporte im Knowledge Graph direkt eingelesen werden – z. B. für eigene Suchindizes, Chatbots, Vergleichstools oder Forschungszwecke:

fetch('https://raw.githubusercontent.com/ThomasBade/website/main/knowledge-graph/data/pages.json')
  .then(r => r.json())
  .then(pages => console.log(pages));

Ergänzend liegen die Seiten auch als JSON-LD-, JSON- und Markdown-Kurzfassungen vor – nützlich, um zitierfähige Auszüge direkt weiterzuverarbeiten, ohne HTML parsen zu müssen.

3. GitHub-Pages-Spiegel nutzen

Unter thomasbade.github.io/website läuft eine automatisch aktualisierte Kopie der Website, inklusive Knowledge-Graph-Dashboard unter /knowledge-graph/. Praktisch, um Änderungen am Quellcode direkt im Browser zu prüfen, ohne einen eigenen Server aufzusetzen.

4. Automatisierung nachvollziehen

Veröffentlichung und Deployment laufen über GitHub Actions (.github/workflows/): Jede Änderung am main-Branch löst automatisch einen neuen Build und ein Deployment auf GitHub Pages aus. Der Workflow selbst ist im Repository einsehbar.

5. Inhalte korrekt zitieren

Für akademische oder redaktionelle Zwecke liegt eine maschinenlesbare Zitierangabe in CITATION.cff vor (GitHub-Zitierfunktion). Autor ist Thomas Bade, maßgeblich für Inhalte bleibt die jeweilige kanonische URL unter www.thomas-bade.de.
